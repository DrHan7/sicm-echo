# Manuscript-to-code methodology audit

This review compares echo_v2.docx with the four supplied Python scripts. The code organization in this release retains the supplied methodological logic. Path handling and output destinations are configurable; no model, preprocessing, hyperparameter, or metric behavior was changed.

Items below need the authors' decision before the manuscript and pipeline can be described as fully aligned. The README reports the implemented behavior rather than smoothing over these differences.

| Topic | Manuscript description | Supplied implementation | Decision to review |
|---|---|---|---|
| LV-segmentation normalization in fivefold CV | Channel-wise normalization is estimated from the corresponding training data and applied unchanged to evaluation data. | The CV script calls preprocess_all(full_df) before creating the five folds. estimate_seg_normalization samples up to 64 videos from the entire development cohort, including IDs later assigned to validation folds, then shares those values across folds. It uses image intensities, not labels, but does use held-out-fold inputs. | Confirm whether the manuscript should describe this transductive normalization or whether the CV preprocessing must be made fold-specific. No change was made. |
| External cardiac-cycle extraction | External videos undergo the same cycle-extraction procedures used during development. | Training and CV use only primary ED peaks (distance=6, prominence fraction 0.05) and fail when fewer than two peaks are found. External inference adds a relaxed pass (distance=4, prominence fraction 0.015), then autocorrelation and extreme-interval fallbacks. Thus a subset of external videos can receive cycles that the development pipeline would reject. | Confirm which detector reflects the reported external results. No detection logic was changed. |
| Supervised loss | The manuscript names binary cross-entropy with logits. | The full-model and CV scripts set USE_CLASS_POS_WEIGHT=True and use pos_weight = n_negative / n_positive in BCEWithLogitsLoss. | Confirm whether to add the class-weighting rule to the manuscript. No loss behavior was changed. |
| Calibration and model-comparison analyses | The manuscript describes calibration curves and Brier score, a paired DeLong test for model comparison, and decision-curve analysis. | CV reports Brier score but does not generate a calibration curve. The supplied external evaluator reports AUROC, bootstrap CI, accuracy, sensitivity, specificity, and F1; it does not calculate external Brier/calibration, paired DeLong, or decision-curve analysis. | Identify the analysis code/results source for the manuscript-reported procedures, or decide whether additional scripts should be supplied. None were invented here. |
| Clinical and sensitivity labels | The manuscript defines external SICM using cTnT thresholds and reports two sensitivity analyses. | Inference reads no labels. The evaluator reads one already-binarized ID/label file per run; it does not derive cTnT labels, apply the 0.20-ng/mL threshold, or exclude the 0.08 to 0.12-ng/mL interval. | Supply/identify the approved label-derivation workflow and use distinct precomputed label files for each analysis. No patient data or label code was added. |
| Cohort construction and descriptive statistics | The manuscript describes Sepsis-3 identification, eligibility/exclusions, index-echo timing, cohort labels, and cohort-level statistical tests. | The supplied scripts start from curated id,label tables and selected .npy loops. They do not implement the clinical cohort query/selection, label derivation, or Mann-Whitney/chi-square/Fisher baseline comparisons. | Confirm whether these procedures are maintained in separate approved analysis code. |
| Full-model training metrics | The manuscript says the final model uses the full development cohort. | train.py uses all labeled development IDs and explicitly labels its reported AUC as in-sample. | Keep the in-sample outputs separate from CV/held-out performance when reporting results. This is an interpretation note, not a code change. |
| Baseline external predictions | The manuscript compares the physiology-informed model with an EchoJEPA baseline. | The evaluator requires both full-model and EchoJEPA baseline prediction CSVs. The baseline inference source was not among the files initially supplied and is pending from the author. | Add the baseline inference source and check its input, preprocessing, and metric path against the manuscript before considering external comparison reproducible. |
| Dependency and checkpoint provenance | The methods identify EchoJEPA ViT-L and EchoNet-Dynamic LV segmentation. | Scripts name the expected checkpoint files, but no checkpoint binaries, training-environment lockfile, or EchoJEPA Git commit were supplied. | Record the exact upstream commit, Python/PyTorch/torchvision/CUDA versions, and checkpoint checksums used for the reported run. The checkpoints remain excluded from this repository. |

## Checks that are consistent

- The CV script deduplicates to one row per ID before applying StratifiedKFold; all cycle instances are then selected through the patient ID. This is patient-level stratification when the input table has one pseudonymous ID per patient, as documented.
- The CV and full-model scripts use the same primary ED peak settings and the same listed SSL/classification epochs and core model dimensions.
- Physiological descriptor means and standard deviations are fitted from training-fold cycles in each CV fold and stored with that fold's model.
- External inference loads the final-model checkpoint and training-derived LV-segmentation normalization; it does not update the model or fit normalization on external labels.
- The supplied external evaluator uses a 0.5 probability threshold and percentile bootstrap AUROC intervals (2,000 resamples, seed 42).

## Scope

The audit is a static comparison of the supplied code and manuscript. No patient data, labels, model checkpoints, or local outputs were used or copied. No training, inference, or statistical analysis was run during preparation of this repository.
