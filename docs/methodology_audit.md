# Manuscript-to-code methodology audit

This static review compares echo_v2.docx with the six scripts in this release. The author-supplied updated CV and external-inference scripts replace earlier versions. Runtime paths and output destinations are configurable for the repository. Method differences introduced by the supplied updates are described below; no modeling choice was silently changed during repository preparation.

## Items to verify before reporting results

| Topic | Manuscript | Current supplied code | Author review |
|---|---|---|---|
| Fold-specific LV-segmentation normalization | Channel-wise normalization is estimated from the corresponding training data and applied unchanged to evaluation data. | The updated CV script estimates normalization separately from each fold's training videos and uses it for both training and validation preprocessing. | This corrects the earlier full-cohort normalization behavior. Confirm that the reported CV results were generated with this updated script and fold-specific normalization. |
| External cardiac-cycle extraction | External videos use the same cycle-extraction procedure as development. | Updated external full-model and baseline inference use only the primary ED-peak detector (minimum peak distance 6; prominence fraction 0.05). They do not use the relaxed detector or autocorrelation/extreme-interval fallback from the earlier full-model inference source. | This aligns the current code with the stated procedure but can change which external studies receive predictions. Confirm that the reported external results used the updated detector. |
| CV preprocessing failures and analysis cohort | The manuscript reports a 530-patient development cohort and patient-level fivefold validation. | The updated CV script assigns all labeled video IDs to folds before cycle extraction. IDs with failed cycle preprocessing are logged and excluded from that fold's training/evaluation; pooled OOF metrics include successful cases only. | Report the number and reasons for excluded IDs, and confirm that the resulting OOF sample and reported results match the manuscript. This differs from the earlier script, which filtered to successfully preprocessed IDs before splitting. |
| Supervised loss weighting | The manuscript names binary cross-entropy with logits. | Full-model, CV, and baseline training use `pos_weight = n_negative / n_positive` in `BCEWithLogitsLoss`. | Confirm whether the manuscript should report class weighting. This changes the fitted classifier relative to unweighted BCE. |
| Direct EchoJEPA baseline specification | The manuscript describes comparison with direct EchoJEPA classification but gives limited implementation detail. | The baseline uses LV segmentation for cycle localization, all adjacent primary-peak cycles, mean pooling over EchoJEPA tokens and then cycles, and an MLP classifier. It does not use LV-area features or self-supervised adaptation. Stage A trains with a frozen backbone for 10 epochs; Stage B fine-tunes the final two blocks for 20 epochs. | Confirm that this exact baseline generated the reported AUROC, and consider adding its preprocessing, pooling, and training details to Methods. |
| Baseline development performance | The paper reports external baseline discrimination and also displays cohort performance summaries. | The baseline training script fits the full development cohort and writes training-set predictions/metrics; these are in-sample, not cross-validated estimates. | If development-cohort baseline performance is reported, label it as in-sample or provide the analysis source for an independent estimate. |
| Calibration and model comparison | The manuscript describes external calibration, Brier score, paired DeLong testing, and decision-curve analysis. | CV reports Brier score. The supplied external evaluator reports AUROC with percentile-bootstrap CI plus accuracy, sensitivity, specificity, and F1 at threshold 0.5. It does not implement the external calibration curve/Brier analysis, paired DeLong test, or decision-curve analysis. | Identify and add the source code used for these reported analyses, or revise the manuscript/results to match the available analysis code. No missing analyses were recreated here. |
| Clinical and sensitivity labels | The manuscript defines development SICM using cardiac criteria and external SICM using cTnT thresholds, with sensitivity analyses. | Inference reads no labels. The evaluator reads one already-binarized ID/label CSV per run; it does not derive labels from clinical variables, apply cTnT thresholds, or exclude the 0.08 to 0.12 ng/mL interval. | Identify the approved label-derivation workflow and verify that each primary/sensitivity label file matches the manuscript definitions. No patient data or label-generation code was added. |
| Cohort construction and descriptive statistics | The manuscript describes Sepsis-3 identification, eligibility/exclusions, index-echo timing, SICM labels, and cohort-level statistical tests. | The supplied scripts start from curated IDs/labels and selected `.npy` loops. They do not implement the clinical cohort query, label derivation, or Mann-Whitney/chi-square/Fisher baseline comparisons. | Confirm whether these procedures are maintained in separate approved analysis code. |
| Full-model training metrics | The final model is described as trained on the full development cohort; internal validation is reported separately. | `train.py` fits the full labeled development set and its training predictions are in-sample. The fivefold script produces the OOF estimate. | Keep final-model training metrics distinct from CV performance. |
| Runtime and checkpoint provenance | Methods identify EchoJEPA ViT-L and EchoNet-Dynamic LV segmentation. | The scripts name expected checkpoint files, but the supplied materials do not include checkpoint binaries, a training-environment lockfile, the study-time EchoJEPA commit, or checkpoint checksums. | Record the exact code commit, Python/PyTorch/torchvision/CUDA versions, and checkpoint identities/checksums used for the reported runs. Checkpoints remain excluded from the repository. |

## Behaviors that are consistent

- The CV split is stratified by patient ID; all cycles from one ID stay in that ID's fold. The updated script also verifies that OOF predictions map back to the assigned fold.
- The updated CV script fits segmentation normalization using training-fold videos only and fits physiological-feature normalization using training-fold cycles only.
- Full-model training, CV, and both external inference scripts use primary ED peaks with minimum distance 6 and prominence fraction 0.05. The external scripts do not fit normalization or update model weights.
- The full model's 16-frame, 224 x 224 EchoJEPA input, LV-area representation, phase-aware modeling, and multi-cycle aggregation are present in the supplied implementation.
- The evaluator uses a 0.5 probability threshold and percentile-bootstrap AUROC intervals (2,000 resamples, seed 42), as described for the supplied metric workflow.

## Scope

This audit is a static comparison of the manuscript and supplied source code. No patient data, labels, model checkpoints, or local outputs were copied. No training, inference, or statistical analysis was run during repository preparation.
